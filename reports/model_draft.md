## 預測任務

在週開始前，為每位測試使用者分別預測未來七天是否至少發生一次 `open_pr`、`open_issue`、`issue_comment`、`pr_review`、`pr_review_comment`、`push`。六項活動可以同時發生。正式測試週為台灣時間 2026/11/22 00:00 至 11/29 00:00。推論以 `test_input.csv` 的 4,465 位使用者為主表，用 `Users.github_user_id` 對接。圖內索引使用該次建表的 `Users.user_id`。 [作業規格](../README.md#4-test-users-and-output) · [使用者欄位](../SCHEMA.md#users)

## 模型架構

使用一個可學習的共用使用者向量 `h0`，有歷史的使用者由 GNN 補上個人修正 `delta[u,t]`。六輸出的線性層同時處理兩組人。將 `h0` 初始化為零，輸出層偏置 `b` 則用訓練週六項發生率的 logit 初始化。發生率先平滑，使某活動在訓練週都未出現時仍有有限的初始偏置。

```text
h[u,t]      = h0 + has_history[u,t] * delta[u,t]
logits[u,t] = W @ h[u,t] + b
p[u,t]      = sigmoid(logits[u,t])
```

`has_history` 依預測切點判斷。使用者有可見的個人活動或有效圖鄰居時才啟用修正。完全缺資料時令修正為零，同一個共用基準輸出六項機率。訓練以 cohort 清單建立 `(使用者, 週切點)` 樣本，包含切點前沒有歷史的使用者。圖中可保留能提供關係的非 cohort 使用者，監督標籤只對 cohort 建立。第一版使用兩層、64 維的異質 GraphSAGE，對使用者向量做六項 `BCEWithLogitsLoss`。使用者 ID 用來對接資料，模型輸入使用歷史特徵與圖結構。 [Cohort 與圖關係](../SCHEMA.md#users)

第一版用七天標籤聯合學習 `h0`、GNN 修正和輸出層。有歷史的樣本會更新兩個分支，無歷史的樣本只經共用向量與輸出層。可選的自監督實驗先在該驗證切分的訓練時段預訓練 GNN，例如遮住一段歷史活動，從其餘上下文預測被遮住的類型，再用七天標籤聯合微調。預訓練偏重學習活動與圖表示，無歷史使用者的六項機率仍由對應的每週標籤校準。

## 圖資料與時間特徵

用原生 PyTorch 的節點特徵及分關係邊張量表示官方前處理後的八張表。每張表是一種節點，每個外鍵欄位是一種有類型的邊。建圖時加入訊息傳遞需要的反向邊。 [建圖程式](../scripts/model_data.py) · [模型程式](../scripts/gnn_model.py)

| 關係 | 圖上的路徑 | 時間資訊 |
|---|---|---|
| A push 到某個 repo | `A → Push → Repo` | push 的 `created_at` |
| A 開 PR | `A → PullRequest → Repo` | PR `created_at` 與 `first_seen_at` |
| B review A 的 PR | `B → PRReview → PullRequest → A` | 依 `pr_id` 配對，保留提交時間與首次可見時間 |
| B 留言在 issue 或 PR | `B → IssueComment → Issue` 或 `B → PRReviewComment → PullRequest` | 留言 `created_at`，PR 對話可透過 `Issues.pull_request_id` 接回 PR |

`reviewer_id` 表示實際提交 review 的使用者。`Pushes` 沒有該次 push 的 commit SHA，因此「A 在該 PR 的 head repo 最近一次 push → B review」只能作時間近似特徵。保留 `User`、事件和 `Repo` 的連線即可表達同 repo 活動。第一版以 `t - event_time` 表示相對時間。 [資料表 Schema](../SCHEMA.md)

- **可見時間**用於建圖與特徵入口。每個切點 `t` 只使用 `row_time < t` 的列，邊的兩端也要已可見。`merged_at`、`merged_by_id`、`closed_at`、`dismissed_at` 等事後更新欄位先排除。
- **事件時間**用於計算相對時間與先後。依活動採 `created_at` 或 `submitted_at`，保留小時級時間差。彙整近 1／6／24 小時與 7／14 天的各類計數、活躍天數、距離上次活動多久。對可配對的 PR 關係可加上開啟到 review 的時間差。
- **觀測範圍**隨窗口保留。先記錄窗口預期時數與實際覆蓋情況，再把可疑的 push 收錄區段另外標記。若在截止前無法補齊 11/18 08:00 後的資料，近時特徵以缺失表示，並在歷史驗證模擬相同尾端缺口。作業推論只使用正式週開始前的資料。 [時間規則與來源限制](../README.md#3-the-tables)

## 訓練、驗證與交付

以七天標籤直接監督。每個歷史切點 `t` 的標籤由事件時間落在 `[t, t+7 天)`、且在該窗結束前已可見的資料列建立。開 issue 排除 PR 對話列。這是由表格產生的活動 proxy。若確認某活動在部分時段未被來源收錄，該週未觀察到的該類活動標籤應視為未知，在訓練損失中略過，並另外報告其覆蓋狀況。 [既有標籤代理定義](../notebooks/01_initial_analysis.ipynb) · [正式評分規格](../README.md#4-test-users-and-output)

### Loss 與類別不平衡

- 每種行為保留可觀察次數 `n` 和二元標籤 `y = (n >= 1)`。主 loss 使用 `BCEWithLogitsLoss`，以每個使用者週與活動類型的可用標籤做遮罩。一週 push 一次與 push 十次，官方標籤同樣都是 `1`。
- 歷史次數保留為輸入特徵。若要利用未來一週的訓練次數，可加一個輔助輸出，在該活動週收錄充分且 `n > 0` 的樣本上預測 `log1p(n)`，用 `BCE + λ × count_loss` 比較有沒有改善二元 F1。活動週有已觀察到的事件，二元正例已知，即使完整次數仍未知。
- 預測「沒有活動」的機率等於 `1 - P(有活動)`。同時反轉標籤與機率，二元交叉熵相同，類別不平衡的程度也沒有改變。先在驗證週用作業分數選各類閾值，再比較 `pos_weight` 是否改善召回率與整體分數。 [PyTorch 二元交叉熵](https://docs.pytorch.org/docs/2.15/generated/torch.nn.BCEWithLogitsLoss.html)

### 歷史切分

| 台灣時間週起點 | 初版用途 |
|---|---|
| 10/4、10/11 | 訓練，14 天特徵附上部分觀測的覆蓋比例 |
| 10/18、10/25 | 訓練 |
| 11/1 | 選模型、每項活動的二元閾值 |
| 11/8 | 最後一次獨立歷史檢查 |

在相同週切點比較 **Copy last week**、**共用基準**、**表格歷史特徵**和**共用基準加圖修正**。對時間做三組比較，依序使用週窗口、加日窗口、再加小時與有序互動特徵。模型選擇依作業分數 `(macro-F1 + micro-F1) / 2`，另列每類 F1 及有／無歷史的分組結果。兩個較晚的週切點 push 收錄量偏低，解讀 push F1 時一併檢查標籤覆蓋。比較時只調驗證週的設定，保留最後一週做獨立檢查。 [官方評分與基準](../README.md#4-test-users-and-output)

正式推論以 `test_input.csv` 保留每一列，依各類閾值轉成 `0` 或 `1`，再用 `scripts/evaluate.py` 檢查使用者及欄位格式。現有圖規模約 9.5 萬個節點、30.8 萬條有向邊（含反向邊）。本機用現有資料、四個 CPU 執行緒跑完預設訓練與 `--refit` 約 14 秒。11/1 驗證週分數為 37.03%，11/8 獨立檢查週為 33.49%，該週 Copy last week 為 32.85%。這些分數根據目前表格產生的 proxy 標籤，試跑只用小時檔清單判斷覆蓋。正式測試分數和 GPU 訓練時間尚待量測。 [主模型執行方式](../SETUP.md#主模型)

### 補資料後共用同一流程

資料目錄、覆蓋起訖、週切點和實驗設定由輸入配置提供。歷史回測保留原來的切點，正式預測切點是台灣時間 **11/22 00:00**，對應 **UTC 11/21 16:00**。要用滿正式切點前的歷史，來源應補到這個截止時間，截止時點本身排除。末週是否成為可用的歷史標籤週，由來源覆蓋及各活動的標籤品質決定。 [正式測試時間](../README.md#4-test-users-and-output)

```text
官方前處理 → 資料覆蓋檢查 → 依切點建圖、特徵與標籤 → 訓練與驗證 → 正式推論
```

更新資料後用同一套程式重建圖、各類可用標籤及統計，節點 ID 對應以該份 Parquet 重查。保留每次輸入資料版本、週切點、特徵定義與覆蓋紀錄，讓舊回測可重現。正式推論與歷史回測共用特徵和建圖邏輯，歷史流程另外產生可用的未來七天標籤。 [Parquet 與對接規則](../SETUP.md#作業規則重點)
