# ASG2 個人特徵 MLP 對照

## 主模型學到的參數

節點 ID 用來對接外鍵和查找張量索引。每種節點用原始特徵作輸入，例如使用者有 76 個數值或指標特徵，push 有 5 個。每種節點共有一組 `Linear → ReLU` 投影，把特徵轉成 64 維向量。兩層 GraphSAGE 接著以邊類型分別取鄰居平均，再學習如何轉換各類鄰居訊號及節點自己的訊號。六項二元交叉熵聯合更新投影、兩層 GraphSAGE、共用向量和輸出層。 [節點特徵](../scripts/model_data.py#L193) · [模型架構](../scripts/gnn_model.py#L36) · [訓練 loss](../scripts/train_model.py#L124)

## 表格實驗設定

每個樣本是一位使用者和一個預測切點。拿當時原本 76 個使用者特徵，經 `Linear(76,64) → ReLU → Linear(64,64) → ReLU` 後加上共用向量，使用原有六項分類器、冷啟動條件及二元 loss。MLP 的前向只吃個人特徵，實驗重用原有資料準備程式決定哪些使用者走共用向量。 [特徵與標籤程式](../scripts/model_data.py)

每週版和每日版都預測切點後七天。每日版用同一段訓練期，加入每兩個週切點中間的各日切點。每筆訓練標籤的七天窗口都在驗證週開始前結束。每日標籤有重疊，樣本數只反映訓練列數。驗證與留出依原本週界線，使用相同的評分和閾值搜尋。每組跑種子 42、57、2026。 [既有圖模型對照](daily_graph_experiment.md)

| 留出週 | 訓練範圍（切點） | 週切點數 | 日切點數 | 驗證週起點 |
|---|---|---:|---:|---|
| 11/1–11/8 | 10/4–10/18 | 3 | 15 | 10/25 |
| 11/8–11/15 | 10/4–10/25 | 4 | 22 | 11/1 |

為了檢查每日版是否只受益於更新次數較多，另一組把每週批次等量重複。兩個留出週的對照分別為每輪 15 對 15 次更新，以及每輪 24 對 22 次更新。重複版的每週切點與標籤和一般每週版相同。用相同的週批次重複規則再跑一次累積圖 GNN，讓它和每週 MLP 有相同的每輪更新次數及驗證頻率。

## 回測結果

| 方法 | 11/1–11/8 | 11/8–11/15 |
|---|---:|---:|
| 原版累積圖 GNN | 33.26% | 32.59% |
| 累積圖 GNN，每週取樣，增加更新次數 | 32.96% | 34.81% |
| 最近七天單張圖 GNN | 33.67% | 33.65% |
| 個人特徵 MLP，每週取樣 | 29.76% | 33.59% |
| 個人特徵 MLP，每日取樣 | 34.55% | 34.83% |
| 個人特徵 MLP，每週取樣，增加更新次數 | 35.00% | 35.09% |

表中為三個種子的平均作業 Score。提高更新次數之後，每週 MLP 在這兩個留出週都追上每日 MLP，並比相同每輪更新設定的累積圖 GNN 分別高約 2.04 和 0.27 個百分點。每日切點會產生較多重疊的未來七天標籤，本次結果支持把純個人歷史特徵當成重要基準，也顯示需控制更新次數才適合解讀取樣頻率。留出資料只有兩週，且標籤以目前的 GitHub 歷史收錄為準。這個比較涵蓋兩種模型架構，無法單獨量出哪些圖關係提供訊號或帶來雜訊。

## 逐日標籤的資料量

現有資料有 47 個完整台灣日，9,000 人共 423,000 個使用者日。按事件發生的台灣日期分組，匯總目前快照中觀察到的活動。以下是資料描述，包含現有快照中補記的事件。實際訓練仍依切分區隔資料。 [現有資料範圍](../SETUP.md#最新建置結果)

| 活動 | 正例使用者日比例 | 每日正例人數中位數 |
|---|---:|---:|
| 開 PR | 0.86% | 73 |
| 開 issue | 0.59% | 50 |
| Issue／PR 討論留言 | 0.59% | 49 |
| 提交 review | 0.58% | 52 |
| PR 程式碼 review 留言 | 0.28% | 22 |
| Push | 3.68% | 119 |

若用 11/1 當驗證切點，要求至少有 24 小時歷史且每日標籤在驗證前結束，可取 29 個訓練日。使用者列數雖多，日期和週期仍少。Push 數受來源收錄影響。

若把七天的逐日標籤 OR 起來和原本週標籤比較，應在各週用相同的標籤可見截止。事件以發生時間放到對應日期，輸入則仍以預測切點可見的 `row_time` 篩選。如果每日標籤也限制在當日結束前必須可見，六個歷史週會比原本週標籤少 7 個開 PR、68 個開 issue 及 22 個 review 的正例使用者週。 [作業的 row time 規則](../README.md#3-the-tables)
